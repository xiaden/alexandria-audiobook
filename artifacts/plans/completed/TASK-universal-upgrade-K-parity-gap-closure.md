# Task: Close Universal-Upgrade Parity Gaps (artifact serving routes, 503 retry mapping, pause disclosure)

## Problem Statement

Follow-up plan closing three parity gaps logged during Plan F execution / QA (Plan F P5-S4, P7-S4 security residual, P7-S5 QA observations; confirmed absent in `app/` source inventory and the Support-Librarian corpus briefing):

1. **MP3/Audacity artifact links 404 in deployment.** `POST /api/pipeline/export/m4b` returns server-side filesystem paths (`mp3_path`, `audacity_path`) that the frontend (Plan F Phase 5, `renderExportCapabilities`) uses **verbatim** as `<a href>` values. Only `GET /download/{job_id}` (m4b) and `GET /export/audio/{job_id}` (playback) have HTTP routes — the mp3 and audacity zip have **no serving route**, so the advertised links 404. Root README documents this at L52-53, L339, L417-418 as a known backend gap.
2. **`ConcurrentTransactionError` → 503 + Retry-After is documented contract text, unimplemented.** CONTRACTS rule #4 / adapter.py docstring (lines 46-52) say "the API layer maps this to HTTP 503 + Retry-After", but `app.py` registers **no** FastAPI exception handler. A CTE escaping a request path (e.g. review accept/reject/override, snapshot merge, `cancel_walks` out-of-transaction write) surfaces as **500** today. Frontend `postWithRetryOnce` (Plan F P2) keys off 503 + Retry-After but the 503 branch is untriggerable in production.
3. **Pause-after is carried but never applied — the UI falsely promises merge behavior.** `_build_chunks` carries `pause_between_speakers_ms`/`pause_same_speaker_ms` (500/250) on every chunk, but the engine (`app/tts.py`, byte-for-byte immutable) reads only `index/text/instruct/speaker` and drops unknown keys. No audible silence is inserted anywhere (`combine_audio_with_pauses` has no callers). The setup-tab tooltips still say "carried through the render boundary **for merge**", implying the merged audio contains the pauses.

### Binding constraints (from CONTRACTS.md / DD)

- **Rule 1 — pipeline-only surface:** new endpoints live in the 7 existing `api_*` modules behind `APIRouter(prefix='/api/pipeline')`; no new app module files; no legacy endpoint names (`test_legacy_removed.py` stays 12/12; `_LEGACY_ROUTE_PATHS`/families must not match). `/api/pipeline/export/...` is a safe family.
- **Rule 2 — `app/tts.py` byte-for-byte untouchable.** Only seam: `app/pipeline/tts_integration.py`.
- **Rule 3 — rows = truth, manifest = derived.** Serving routes dispatch off `render_job`/`render_chunk` rows, never the in-process `_render_jobs` dict.
- **Rule 4/6 — `ConcurrentTransactionError`:** owner-thread guard + `BEGIN IMMEDIATE` timeout raise CTE; walk-side `_retry_write` (runner.py) retries idempotent writes with 50-100ms backoff — **unchanged**. The new 503 mapping only covers request paths.
- **Rule 10 — 409 + Retry-After:5 snapshot semantics are live and must be preserved** (`POST /projects/load` while a `walk_run`/`render_job` is active). Frontend retries by status code: 503 branch (default) vs 409 branch (projects load) are distinct — the new 503 mapping must not change 409 behavior.
- Path/size/security checks from Plan C review: `_resolve_within_run_dir` realpath containment, `FileResponse404` JSON 404s, Range-DoS guard, hardcoded artifact names (no user input in paths).

### Design decision — Gap 3 is capability disclosure, not silence insertion

True audible silence with the **correct two-value semantic** (500ms between different speakers / 250ms same-speaker continuation) requires per-chunk speaker identity. Neither `render_chunk` rows (`job_id, idx, status, wav_path, error`) nor `manifest.json` (derived, no speaker field) persist speaker — inserting silence would require a schema migration + speaker persistence, overriding the recorded Plan J decision ("no audible-silence insertion: cannot-restore #5", DD cannot-restore #5). A uniform-gap approximation would violate the two-value semantic. **Therefore: explicit capability disclosure** — the export response discloses `pauses_applied: false` + a message, the UI surfaces it, the pause-field copy is made honest, and docs record the limitation. This is the contract-compliant, safest pipeline-native behavior.
