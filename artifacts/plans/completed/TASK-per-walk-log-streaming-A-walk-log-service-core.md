# Task: Per-Walk Log Streaming Part A — Walk-Log Service Core

## Problem Statement
Part A establishes the backend service seam used by later runner and SSE plans. It
must own one process-local JSONL sink and one thread-safe broker per validated run ID,
without changing `runner.py`, `api_walks.py`, `_llm_helpers.py`, or any of the nine
`walk_2*.py` modules. The sink is authoritative for ephemeral replay on disk; the
broker provides bounded live delivery to an asyncio SSE consumer without timers,
file polling, SQLite polling, or blocking the synchronous walk writer.

**Prerequisite:** None. This is the first plan in the A → B → C → D feature chain.

## Public Contracts for Parts B and C
- `WalkLogService(root_dir: str = "/tmp/alexandria-walks") -> None` is the process-owned service.
- `WalkLogService.start() -> None` creates `root_dir` with mode `0700` and removes only UUID-named `*.log` files older than 24 hours; it is idempotent.
- `WalkLogService.shutdown() -> None` marks every open run `partial`/`aborted`, publishes its terminal record when possible, closes sinks/subscribers, and releases broker state; it is idempotent.
- `WalkLogService.open_run(run_id: str, book_id: str, walk_name: str, started_ms: int | None = None) -> WalkLogSink` validates the canonical UUID, creates `{root_dir}/{run_id}.log` with mode `0600`, writes/flushed a bounded header, and registers the run sink/broker. It rejects duplicate active run IDs.
- `WalkLogService.get_run(run_id: str) -> WalkLogSink | None` returns the active sink without creating one; it is read-only and thread-safe.
- `WalkLogService.open_subscription(run_id: str, after_seq: int = -1, loop: asyncio.AbstractEventLoop | None = None) -> WalkLogSubscription` replays the authoritative file for active or completed runs, then atomically registers a live subscriber on the broker lock to bridge records after the file tail; it raises `KeyError` for an unknown in-process run/file.
- `WalkLogService.close_run(run_id: str, status: Literal["completed", "failed", "cancelled", "interrupted"] , payload: Mapping[str, Any] | None = None) -> WalkLogRecord | None` appends the final terminal record, publishes it before closing the broker, closes the sink, and removes the run from active state. The terminal record is last and is attempted even after ordinary-record overflow.
- `WalkLogService.replay(run_id: str, after_seq: int = -1) -> tuple[WalkLogRecord, ...]` reads complete JSONL records from the validated run file, ignores/logs a partial trailing line, and returns records with sequence greater than `after_seq`; it never follows a path derived from unvalidated input.
- `WalkLogSink.append(event: str, payload: Mapping[str, Any] | None = None, *, terminal: bool = False) -> WalkLogRecord | None` is the synchronous writer-facing append operation. It serializes UTF-8 JSONL, redacts secrets, enforces prompt/response 64 KiB, traceback 32 KiB, and event 128 KiB limits, projects encoded bytes before every append, flushes every successful write, and is safe for concurrent callers. Ordinary records that would consume the 64 KiB terminal reserve are dropped and return `None`; the file-cap overflow marker, when emitted, is a real file record with a real sink sequence.
- `WalkLogSink.append_terminal(status: str, payload: Mapping[str, Any] | None = None) -> WalkLogRecord | None` is the terminal-only convenience operation and guarantees compact terminal delivery within the reserved space when the filesystem permits.
- `WalkLogSink.close_partial(status: Literal["partial", "aborted"] = "aborted") -> None` closes an unfinished sink after publishing its bounded terminal marker when possible; it is idempotent.
- `WalkLogSubscription.replay -> tuple[WalkLogRecord, ...]` is the immutable atomic replay snapshot captured during subscription.
- `WalkLogSubscription.next_event() -> Awaitable[WalkLogRecord | None]` waits for the next record or closed broker using loop-safe notification scheduled with `loop.call_soon_threadsafe`; it uses no timer or polling.
- `WalkLogSubscription.close() -> None` removes the subscriber without blocking or changing the walk; it is idempotent. `WalkLogSubscription.__aiter__()` yields replay/live records for the later SSE generator.
- `WalkLogRecord` is the immutable normalized record DTO with `run_id: str`, `seq: int`, `id: str`, `event: str`, `data: Mapping[str, Any]`, and `terminal: bool`; IDs are `{run_id}:{seq}` and sequences are monotonically increasing per run.
