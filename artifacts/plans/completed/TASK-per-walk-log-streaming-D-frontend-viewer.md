# Task: Per-Walk Log Streaming Part D — Frontend Viewer

## Problem Statement
The Script tab currently rebuilds walk-run history with `innerHTML`, destroying
live viewers on each 2-second status refresh. Add keyed per-run SSE viewers while
preserving polling, module-scope initialization, and DOMContentLoaded wiring.
Scope is `frontend/src/tabs/script.ts` and focused Vitest coverage; consume the
Part C contract without backend or walk-module changes.

**Prerequisite:** `TASK-per-walk-log-streaming-C-sse-endpoint.md`.

### Phase 3: Implement EventSource lifecycle and bounded safe rendering
- [x] Open one `EventSource` at `/api/pipeline/walks/log/{run_id}` using only the server-provided run ID; already-open runs are no-ops and stale rows cannot attach callbacks.
    **Note:** openWalkLog now opens exactly ONE EventSource at `/api/pipeline/walks/log/${runId}` using ONLY the server-provided run ID, created only when `logEntry.source` is null (every close path nulls it) and the run isn't already open (existing `entry?.open` no-op). Stale rows cannot attach callbacks: every handler begins with `if (!walkLogRegistry.get(runId) || !logEntry.open) return` so a removed/closed entry never touches the DOM. Reopened entries refresh node refs but keep renderedIds; source = new EventSource url; logEntry.source = source lands the reserved Phase-2 field.
- [x] Parse `log` JSON, validate/use its opaque event ID, ignore rendered IDs across reconnects and refreshes, and append bounded readable timestamp/event/selected-data fields with text nodes/`textContent` only.
    **Note:** 'log' handler parses evt.data JSON in try/catch (malformed payloads absorbed silently — the test verifies a valid record still renders afterward). Dedup key = the record's opaque `id` ({run_id}:{seq}); fallback builds `${run_id}:${seq}` from the record fields when id is missing/invalid. renderedIds persists across close/reopen (reconnect) and status refreshes — overlapping replay ids are skipped, only new seqs append (verified by the reconnect and reconcile tests). Rendering is textContent-only via buildLogEntryText: `[formatWalkRunTime(timestamp)] event\nprompt[system]: …\nprompt[user]: …\nresponse: …` appended as one div[data-walk-log-entry] — hostile values are literal text (escapeHtml is identity in tests; zero elements created).
- [x] Enforce fixed client caps for rendered elements and per-record text so replay or large payloads cannot grow the DOM unboundedly; retain IDs for the viewer entry lifetime.
    **Note:** Fixed client caps added as module constants WALK_LOG_ENTRY_CAP=200 (rendered entries per viewer), WALK_LOG_RECORD_TEXT_CAP=500 (rendered chars per entry), WALK_LOG_STATUS_TEXT_CAP=200 (status chars). Entry cap: once renderedCount >= 200 the id is still added to renderedIds (dedup stays correct) but no element is created — 230 unique ids produce exactly 200 entries. Per-entry text is sliced to 500 chars (800-char response renders ≤500). Status text (complete/410/error) sliced to 200. renderedIds live for the viewer entry lifetime: closeWalkLog keeps the entry, only row-removal/empty-payload/detached-row paths delete it.
- [x] Handle `complete` by updating stable status and closing/removing the source; handle 410 and other errors with bounded status messages and cleanup according to the contract; make all close/removal paths idempotent.
    **Note:** 'complete' {run_id,status}: publishes bounded status text (payload.status, fallback 'Completed', sliced to 200) into #walk-log-status-{rid} then closeWalkLogEntry(runId, entry, false) — guarded source.close (closed-flag so an externally-closed source isn't closed twice), source=null, open=false, viewer hidden, entry KEPT so renderedIds survive; double complete is a no-op (closeCount stays 1) and late events hit the registry/open guard. 'error': numeric `status` (410 Gone) read defensively via (evt as {status?: unknown}) with a typeof number check — real browser ErrorEvents carry no status → generic 'Log stream connection failed.'; both publish bounded text (matches /410/ under cap) and close exactly once, open state resets so a subsequent click can reopen (completed run replays + re-completes, deduped). With `source` landed, the P2 removal paths now close REAL live sources (row vanished → closeWalkLogEntry delete=true; empty payload → closeAllRegistryEntries; detached rows → purge). All close/removal paths idempotent.
