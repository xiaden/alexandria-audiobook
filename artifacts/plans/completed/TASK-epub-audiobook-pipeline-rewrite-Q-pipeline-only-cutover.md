# Task: Pipeline-Only Cutover and Legacy Code Deletion

## Problem Statement

Plans A–P have made the SQLite-based pipeline the feature-complete product path: 9-walk serial DAG, operation executor, assembly/export, TTS integration with duck-typed `render_audiobook`, 25 pipeline endpoints, voice catalog CRUD + preview with 5 voice types, persisted character assignment, configurable narrator with Ryan fallback, and pipeline-first frontend tabs (script, voices, editor, setup).

A large dual-path legacy surface still coexists with the pipeline and must be **deleted**, not deprecated. The user requires the pipeline as the sole product path — no toggle, no compatibility shims, no 410 fallbacks (Plan H precedent: "DELETE, don't deprecate"). Verified legacy surface (research, Aug 2026):

- **Backend legacy flow** in `app/app.py`: `project_manager` (app/project.py `ProjectManager`, 1004 lines) used by ~30 call sites; chunk endpoints (`/api/chunks*`, `/api/annotated_script*`, `/api/scripts*`, `/api/status`, `/api/upload`, `/api/audiobook`, `/api/unload`, `/api/cancel_audio`), legacy voice endpoints (`/api/voices`, `/api/save_voice_config`, `/api/cancel_persona`), legacy merge/export/batch endpoints (`/api/merge`, `/api/audiobook_m4b`, `/api/m4b_cover`, `/api/export_audacity`, `/api/generate_batch`, `/api/generate_batch_fast`), legacy Pydantic models (`VoiceConfigItem`, `ChunkUpdate`, `BatchGenerateRequest`, `PromptConfig`, `GenerationConfig`), and `CONFIG_PATH`-adjacent constants (`SCRIPT_PATH`, `VOICE_CONFIG_PATH`, `AUDIOBOOK_PATH`, `M4B_PATH`, `CHUNKS_PATH`, `SCRIPTS_DIR`, `UPLOADS_DIR`).
- **Orphan prompt/config files**: `app/default_prompts.py`, `app/review_prompts.py`, `app/persona_prompts.py` + `default_prompts.txt`, `review_prompts.txt`, `persona_prompts.txt` — consumed only by legacy `/api/config` prompts section, `/api/default_prompts`, and `setup.ts` UI. The pipeline reads config from the walk request body (`config: dict` in `RunWalkRequest`) and never reads the `prompts` or `generation` sections (verified: zero consumers in `app/pipeline/`). `state.json` is legacy-only (`current_file` in config GET; written by `/api/upload`).
- **Frontend legacy surface**: `tabs/editor-legacy.ts` (738 lines, 17 chunk-editor functions), `tabs/audio.ts` (172 lines, exportAudacity/M4B/cover upload), legacy branches in `script.ts` (10 `pipelineEnabled` refs), `voices.ts` (11 refs: `loadLegacyVoices`, `collectVoiceConfig`, `debouncedSaveVoices`, `toggleVoiceType`), `setup.ts` (`handlePipelineToggle` + prompt/generation sections), `templates.ts` `createVoiceCard` (dead after voices.ts cleanup), `state.ts` `pipelineEnabled` + `setPipelineEnabled` + localStorage key, `api.ts` legacy upload/audio functions, and legacy UI in `frontend/index.html` (audio tab, `#pipeline-toggle`, `#pipeline-disabled-notice`, `#legacy-script-section`, `#legacy-voices-section`, chunk table, legacy editor buttons).

Vitest is **not installed** (frontend tests never runnable; `test_setup.test.ts` header documents this).
- **Docs**: CONTRACTS.md (`get_tts_engine` contract line ~567-574 references `project_manager`; line ~355 documents legacy `debouncedSaveVoices` fallback), parts README.md dependency graph (stops at P), root README.md + README_CN.md (legacy dual-mode docs), frontend/README.md (documents editor-legacy.ts + pipelineEnabled), SKILL.md (extensive legacy refs), VOICE_REFERENCE.md, lora.md, walk-definitions.md (stale v2).

- **Plan P (frontend UX fixes)** — COMPLETE (index contract, span text edit, render/merge/download, state persistence). Uncommitted working-tree changes from P exist; Q builds on the post-P tree state.

## Negative Constraints (hard, non-negotiable)

- **No toggles, no shims, no half-migrations.** `pipelineEnabled` is removed entirely. Legacy code is deleted, never deprecated (Plan H precedent).
- **TTSEngine is untouched.** `app/tts.py` (class `TTSEngine`, `generate_batch(chunks, voice_config, output_dir, batch_seed=-1)` contract: chunks have exactly `{index, text, instruct, speaker}`) and `render_audiobook` signature are preserved byte-for-byte.
- **All 25 pipeline endpoints preserved**, including `PUT /api/pipeline/span/{span_id}/text`, `POST /api/pipeline/render`, `POST /api/pipeline/cancel_render`, `POST /api/pipeline/merge`, `GET /api/pipeline/download/{job_id}`, `GET /api/pipeline/render_status/{job_id}`, voice CRUD + `POST /api/pipeline/voices/{voice_id}/preview`, `PUT /api/pipeline/characters/{id}/voice`.
- **Voice data model preserved**: `voice_config` DB table (12 columns), 5 voice types (`custom|clone|builtin_lora|lora|design`), `NARRATOR` DB-first row with Ryan fallback, `default_style` alias behavior. Do not regress `scripts/seed_voice_catalog.py`, `scripts/migrate_voice_config_schema.py`, `scripts/migrate_voice_config_json_to_db.py`.
- **WALK_ORDER/WALK_TASK_NAMES contract** (3 places: `app/pipeline/walks/order.py`, `frontend/src/pipeline/walks.ts`, tests) and the walk-order sync test are untouched.
- **Canonical API split structure preserved** (`app/pipeline/api.py` includes sub-routers; storage dependency canonical owner stays in `api_onboard`).
- **Negative-space verification**: every deletion is proven by a test asserting absence, not by "grep shows nothing".
- **No dead TODOs, no placeholder stubs, no 'unverified' claims.** Anything not executed is marked explicitly as not executed.
- KEEP endpoints that stay in `app/app.py` (voice designer, clone voices, LoRA, dataset builder, preparer, `/api/config`, `/api/system/stats`) keep working; their `project_manager` engine access is re-pointed at the new engine factory, behavior unchanged.
