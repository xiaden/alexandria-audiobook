# Task: Per-Walk Log Streaming Part B — Runner Integration

## Problem Statement
Part A provides the process-owned `WalkLogService`/`WalkLogSink` seam. This plan
wires that seam into the synchronous walk runner and shared LLM helpers without
editing any of the nine walk modules. It moves run identity ownership to the
API-side reservation contract: callers generate canonical UUIDs and persist
`pending` rows, while the runner consumes only those reservations. Existing
database status, result, and error behavior remains authoritative.

The implementation must be tests-first, preserve helper return values, redact and
bound secret-bearing log payloads through the Part A sink, and reset the sink
`ContextVar` on every terminal path, including setup failures and cancellation.
Part C will call the reservation helpers and own the HTTP endpoint; this plan does
not implement or redesign that endpoint.
