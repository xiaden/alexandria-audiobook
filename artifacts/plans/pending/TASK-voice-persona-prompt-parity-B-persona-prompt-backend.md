# Task: Voice-Persona-Prompt Parity B — person + persona and effective prompt/settings backend

## Problem Statement

This is part B of the implementation plan for `artifacts/designs/pending/DD-voice-persona-prompt-parity-browser-external-validation.md`. Part A (contracts/schema/clone-reference backend) is a prerequisite. This part delivers the two remaining backend surfaces, both built on the tables and contracts registered in A: (1) manual persona editing (GET/PUT `/api/pipeline/characters/{id}/persona`, GET `.../persona/revisions`, POST `.../persona/validate`, POST `.../persona/rerun`) revisioned against the character ledger, and (2) effective prompt/settings view/edit/validate/save/rerun for the fixed nine-walk pipeline (`GET /api/pipeline/walks/{book_id}/config`, POST `.../config/validate`, POST `.../config/revisions`, POST `/api/pipeline/walks/{book_id}/reruns`). Both must be versioned, ownership-bounded, side-effect-free on validate, rerun-protected, and register their routes/DTOs in CONTRACTS.md (part A registered the contract IDs; B ensures every route in them is implemented). The combined-walks workbench (2b/2c/2d) is PROTECTED: persona and prompt writes/reruns for those walks delegate to the existing combined-walks contracts and single writer, never duplicating registration.
