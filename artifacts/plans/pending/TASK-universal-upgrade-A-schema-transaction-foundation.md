# Task: Schema & Transaction Foundation

## Problem Statement

The Alexandria audiobook pipeline (Plan Q cutover, pipeline-only mode) uses a single SQLite connection (`SQLiteAdapter`, `check_same_thread=False`) with an implicit auto-commit model: each `execute_insert/update/delete` commits only when the connection was not already in a transaction. There is no `BEGIN IMMEDIATE`, no owner-thread guard, no `busy_timeout`, and no transaction context manager. The Universal Upgrade design (DD-universal-upgrade) requires concurrent walk/render writers that must serialize on one connection: LLM calls happen outside any transaction, and DB writes are batched into short `BEGIN IMMEDIATE` transactions. Without an explicit, guarded `transaction()`, a render thread and a walk thread can interleave commits, deadlock on the single connection, or silently interleave partial multi-statement updates (today only `SAVEPOINT` per-unit writes exist — mid-walk crashes leave earlier units committed).

This plan is the foundation: it makes the SQLite layer concurrency-safe and creates the 6 new tables + 3 indices + `book.single_speaker` column that every later plan (jobs, runs, review items, overrides, snapshots) writes into. It implements TDD, ruff, pytest with coverage, and re-runs the 12-check legacy guard to prove no pipeline-only regression.
