# Task: Repair Pause Insertion and Add User-Tunable Pause Controls

## Problem Statement
Plan K made the pause limitation honest, but the render pipeline still never calls the existing pause consumer. `app/tts.py` already provides `combine_audio_with_pauses` and `compute_timeline`; those functions must remain byte-for-byte unchanged and TTSEngine public signatures must remain unchanged. The next pipeline-native plan restores audible silence, persists safe project/config defaults, supports nullable per-span `pause_after` (including intentional `0`), exposes editing controls, and reports whether the final artifacts actually contain pauses.

This plan supersedes Plan K's capability-disclosure decision (#13) and the DD's cannot-restore pause-after note only for this pause feature. It does not resurrect legacy routes or merge behavior. Existing render, voice, row-authority, export, snapshot, cancellation, and security contracts remain in force.

Audio inputs are currently file paths: batch output is sorted `chunk_*.wav` files and individual output is `render_chunk.wav_path`; neither rows nor manifests contain speaker identity. Therefore the postprocessor must run during `render_audiobook`, while the in-memory script/chunks still contain speakers and pause metadata. It shall load WAV paths as `pydub.AudioSegment` objects, call the existing helper, export a deterministic paused intermediate/final WAV with the source format explicitly preserved, atomically publish it, and clean temporary files on success and failure. It must not mutate `app/tts.py`.

## Dependencies
- Depends on completed Universal Upgrade Plans A–K, especially persisted render jobs/chunks, raw-JSON config merge, project snapshots, export routes, and Plan K's pause disclosure.
- Uses existing `app.tts.combine_audio_with_pauses` and `compute_timeline`, existing pydub dependency, existing `PipelineStorage`/transaction discipline, and existing `/api/pipeline` routers.
- Downstream work must not change TTSEngine public signatures, legacy route guards, or the 409/503 retry contracts.

## Negative Constraints
- Do not edit `app/tts.py` (byte-for-byte) or add a second TTS engine pause implementation.
- Do not add legacy endpoints, compatibility shims, new app modules, unsafe user-controlled filesystem paths, shell commands, or unbounded pause values.
- Do not infer speakers by filename or manifest order after render; use the render-time script/chunks and parameterized persisted metadata only.
- Do not silently coerce missing pause values to zero; `NULL` means default and `0` means an intentional no-gap override.
- Do not claim `pauses_applied: true` until the paused assembly is present and used by every final export surface.
